# DIALOGUE GUIDE — 한 선임과 메신저 (v5)

> 낱말(2026-10-15, 사용자 승인): 플레이어가 보는 말에서 「기록 다시 쓰기」 → **「역사 고정」**, 쓰는 줄 → **「고정할 문장」**, 확인 → **「길게 눌러 역사 고정」**, 상태 「복원됨」 → **「고정됨」**, 실록과 안 맞은 줄 → **「흐릿함 — 그날에 붙지 않았다」**(증인만 본 회색 줄은 「실록이 적지 않은 일」 그대로). 한 선임 대사의 「다시 써/써 봐/돌아왔네」 → 고정 말씨. 내부 이름(rewrite·restore·ev.write_*)은 그대로. 마지막 필수 이름을 붙이면 한 선임이 한 줄(Ep0 `ev0.king_named` 「이제 고정해 봐.」, Ep1 은 닫힘·모순이 남아 `h_write_open` 「이제 고정할 수 있겠다. 홈에.」).

> 설계 원천: `DESIGN_V5.md`(에피소드 1 은 §13 검증 반영본 기준). 화면: `UI_STYLE_GUIDE.md` §2.8.
> 한 선임(가상, `fictional`)은 기록대조과 동료다. **해설자가 아니다.** 그녀는 자기 일을 하면서 07 과 짧게 말을 주고받는다.

## 1. 규칙

1. **말풍선 하나 = 문장 하나.** 길면 나눈다. 한 말풍선 최대 약 30자.
2. **반말, 짧게.** 한 선임은 반말, 07(플레이어)은 존댓말. 이모지 없음. 말줄임은 「…」 하나만.
3. **동료지 해설자가 아니다.** 세계 규칙은 **게임 전체에서 한 번씩만**, 한 사건에 한 문장 이하로, 일하는 사람의 말투로만("관측기는 그날 기록에 이름 남은 사람 눈으로만 봐." — 그날을 「적은」 사람이 아니다: 사초를 쓴 김일손의 눈은 열리지 않는다). 사건의 의미·역사 해설을 길게 하지 않는다. Ep0 에서 말한 규칙(관측기의 눈, 지워지면 기억도, 관측기는 구멍을 잡는다, 고정하면 세상이 굳는다)은 Ep1 에서 다시 말하지 않는다.
4. **정답 금지.** 인물 이름(플레이어가 아직 붙이지 않은), 연도, 사건 이름(무오사화 — 복원 전)을 말하지 않는다. 방향(어디·언제·무엇을 맞대 볼지)만. 검증기가 검사한다.
5. **이야기 사건에만 말한다.** 정해진 순서가 아니라 사건(눈 열림·닫힘, 찾기, 복원)이 말을 부른다(§3). **틀린 시도에는 말하지 않는다** — 판정 줄·도장·토스트가 이미 알린다. 막혔을 때만 힌트 사다리가 말한다(§1-11).
6. **답장은 내 차례에만.** 그녀의 말이 끝나고 질문으로 끝났을 때만 선택지 2~3개. 답이 필요 없는 말도 많다 — 그냥 계속 플레이해도 된다.
7. **그녀도 일한다.** 「찾아볼게」 → 몇 분 뒤 결과. 그동안 상태는 「자리 비움」, 읽음 표시가 늦다.
8. **복원 뒤에는 다른 사람이 된다.** 소실 세계에서 한 말 일부는 복원 때 대화 기록에서 조용히 다시 쓰인다(§4.8). 그녀는 그 사실을 늘 알던 사람이다.
9. 오 실장(가상)은 두 번만 말한다(시작, 06:00). 건조한 반말, 규정의 목소리.
10. **현실 재기록은 대화 기록 전체를 덮는다.** 복원되면 지난 줄 가운데 새 현실과 어긋나는 것은 **모두** 그 자리에서 다시 쓰인다 — 동료의 말도, **07 이 보낸 답도**. 새 현실과 어긋나는 줄은 기록에 하나도 남지 않는다. 내 말까지 바뀌는 것이 이 장면의 서늘함이다(사람의 기억도, 평범한 기록도 보호되지 않는다).
    - **조용히 바뀐다.** ⟲ 표시·원문 보기·길게 누르기 없음. 원래 글을 기억하는 것은 플레이어의 머리뿐이다. **효과도 없다**(먹 번짐·깜빡임 없음 — 2026-10-15 사용자 결정). 메신저는 보통 대화창에 지금 글만 보이고, 플레이어는 거슬러 올라가 볼 때만 알아챈다. 이 문서의 `⟲` 는 작가용 표기일 뿐이다.
    - 동료는 옛 글을 결코 인정하지 않는다(물으면 「내가 언제?」 — 선택, 한 번).
    - **기억 규칙(하나, 2026-10-17 — STORY_BIBLE §2 ④).** 사람의 기억은 보호되지 않는다 — **07 도.** 소실 때도 고정 때도 07 의 머리는 세상을 따라간다: 고정되면 07 도 새 현실을 「원래 알던」 사람이 된다(그래서 복원 뒤 「무오사화요.」라고 답할 수 있다). 빈자리가 있었다는 것을 아는 것은 **관측기 기록뿐**이다(관측기 줄·찾기 기록·본 것). 원래 글을 기억하는 것은 **플레이어의 머리뿐** — 그것이 긴장이다. 07 의 독백은 기억이 아니라 관측기 기록에 기대 말한다(「그 칸이 비어 있었다는 것은 이제 관측기 기록에만 남아 있다.」). 복원 뒤 첫 관측기 줄은 「관측기: 내 관측 기록은 그대로」.
    - **복원 뒤 글은 소실 세계의 답을 미리 말하지 않는다.** 다시 쓰인 줄이 복원 뒤 새 말(예: 「한글 만든 사람?」)보다 먼저 정답을 말해 버리면 대화가 메아리가 된다 — 다시 쓴 줄은 주어 없이 「같은 칸이야」처럼.
    - **06:00 의 낱말은 하나: 「끊김」(2026-10-17).** 관측기 줄 「관측 1개 끊김」, 알림 「관측이 끊겼다」, 동료의 말(「…끊겼어?」, 「끊긴 관측은 끊긴 거야」, 「흐린 데는 그때 끊길 수 있어」), 카드 「관측: 끊김」. 화면 글에 「닫힘」을 쓰지 않는다(작가용 문서의 기제 이름 「눈 닫힘」은 그대로).
    - **관측기가 말한 것은 남는다.** 관측기 줄(「관측기: …」 — 찾음·끊김·「관측 안 됨」)과 그것을 전하는 말(「그중 한 꼭지 문장에 구멍이 났어」, 「이름은 남고 사유가 빠진 거」)은 관측기의 기록이라 소실·복원을 타지 않는다 — 새 현실에서도 참이다.
    - 작성법: 에피소드는 소실 세계에서만 참인 사실을 `erasedFacts`(id·설명·검사 무늬 `tells`)로 적는다. 그 사실에 기대는 줄(say·선택지)은 `facts: [...]` 를 달고 `restored`(복원 뒤 글, 문장 하나·≤30자, 07 은 존댓말)를 갖는다. 검증기 ⑫ 가 강제한다(§5).
    - 바뀐 줄을 따로 모아 보여 주는 화면은 없다(복원 단계 「메시지」 삭제). 복원 뒤 새 말(`ev.restore`)은 보통 대화창에 온다(Ep0 은 다리 장면의 대화창, Ep1 은 메신저). 다음 에피소드로 넘어가면 바뀐 글이 굳는다(원래 글은 저장에만 `bakedFrom`).

11. **말수 예산(2026-10-15 플레이테스트 「선배가 너무 말이 많음」, 검증기 ⑬).**
    - **화면이 이미 보여 주는 것을 말하지 않는다.** 「맞네.」「붙었다.」「카드 하나 더 붙었네.」「아닌가 보네.」「고정이 안 됐네.」 같은 맞장구, 「이름 붙이면 카드 줄에 붉은 밑줄이 가.」「줄 안 이름도 눌러 볼 수 있어.」 같은 UI 설명은 쓰지 않는다 — 도장·토스트·판정 줄이 한다.
    - **틀린 시도 반응 없음.** 미끼·틀린 태그·고정 실패·일부만 고정 같은 사건에 묶음을 두지 않는다(엔진은 사건을 부르지만 대본이 없으면 조용하다). 힌트 사다리만 말하고, 막혔을 때(시간·실패 문턱 — 첫 단은 실패 2회 이상) 또는 07 이 「어디부터 볼까요?」라고 물을 때만. 사다리는 2~3단, 단마다 볼 곳 하나.
    - **사건 하나 = 한 선임 말풍선 ≤3**(가장 긴 갈래 기준, 선택지 뒤 말까지). 현실 재기록 장면(`ev.restore`)만 ≤4.
    - **에피소드 한 선임 대본 줄 상한**(모든 갈래 합, 힌트·빠른 질문 답 제외): Ep0 ≤15, Ep1 ≤35, 그 밖 기본 35. 오 실장 줄은 세지 않는다(두 번만 말한다 — §1-9).
    - 검증기 ⑬(`src/core/validate.ts` `HAN_PER_EVENT_MAX`·`HAN_LINES_MAX`)가 빌드·테스트에서 강제한다. 줄을 더하려면 다른 줄을 빼라.

- **낱말(2026-10-15, `docs/WORDING_AUDIT.md`)**: 우리가 쓰는 말(메시지·힌트·본 것·조각 이름)은 지금 한국어로 쓴다(전교 → 임금의 명령, 서안 → 책상, 서리 → 심부름꾼, 먹선 → 붉은 밑줄). SF 말은 「관측기」 하나 — 시스템 줄은 「관측기: …」 꼴(좌표·재계산·DB·동기화·로그 금지). 국역 인용은 글자를 바꾸지 않고 어려운 말에 탭 풀이(20자 이내)를 단다.

## 2. 타이밍 모델

```ts
// 문자 수 n = 공백 제외 글자 수
typingMs(n)   = clamp(500 + 55 * n, 700, 3800)        // 10자 ≈ 1.05s, 30자 ≈ 2.15s
gapMs()       = 1000 + rand(0, 2000)                   // 같은 묶음의 다음 말풍선까지(입력 중 표시 전 공백)
gapHeavyMs()  = 2500 + rand(0, 1500)                   // weight: 'heavy' 다음
readMs()      = online ? 800 + rand(0, 1700) : away ? 20000 + rand(0, 40000) : -  // 내 말에 '읽음'
replyDelay()  = readMs() + 600 + rand(0, 1400)         // 읽고 나서 입력 시작까지
hesitation:   p = 0.12 (기본) / 0.45 (weight: 'heavy') / 0 (직전 말풍선이 망설임이었으면)
              → 입력 중 700~1400ms → 사라짐 500~1200ms → 다시 입력 중 typingMs(n)
asyncResult:  max(40s~90s 실시간, 플레이어의 다음 '완료 행동') , 상한 120s
```
- 난수는 저장 슬롯 시드로 고정(재현 가능, 테스트 가능). 설정 「메시지 빠르게」 = 모든 시간 × 0.4, 망설임 없음.
- **끼어들기 규칙**: 스크립트 사건이 아닌 자발 메시지는 90초에 하나까지. 플레이어가 손가락을 대고 있는 동안(밀기·시트 조작) 보내지 않고 손을 뗀 뒤 600ms 에 보낸다. 다른 화면에 있으면 위쪽 한 줄 배너(2.5s).
- 묶음(burst) 하나는 최대 4말풍선(오 실장·시스템 줄 포함). 그 이상이면 플레이어가 메신저를 열 때까지 기다린다. 한 선임 말풍선은 §1-11 예산을 따른다.
- 같은 사다리 힌트는 최대 3통, 상황 시작 뒤 30초 침묵(DESIGN_V5 §7).

- ⑬ 말수 예산: 사건 하나에 한 선임 말풍선 ≤3(가장 긴 갈래, `ev.restore` 만 ≤4), 에피소드 대본 한 선임 줄 Ep0 ≤15 · Ep1 ≤35(§1-11).
