## 0. 먼저 — 오진 정정
원본 e2e 스크린샷 몇 장은 연출 도중에 찍혀 버그처럼 보였다. 연출이 끝난 뒤(1.1초) 다시 찍어 확인한 결과 **버그가 아니었다**:
- 근무 보고 종이가 관측 창에 잘려 보임(`mobile-20`, `mobile-34`, `mobile-50`) → 인쇄 연출(0.9s, steps) 중간 프레임. 끝나면 정상(`review/before/mobile-20`).
- 복원된 낱말이 흐림(`mobile-09` 이극돈, `mobile-34` 홍귀달) → 먹 번짐 1.6s 중간. 끝나면 선명.
- 바랜 07 확대에 "나는 이 도장을 찍은 기억이 없다"가 없음(`mobile-18`) → 1.1s 지연 페이드 중. 있음.
- 에필로그 종이 반투명(`mobile-51`), 예고 보고서 글자 흐림(`mobile-52`) → 순차 페이드 중.

e2e 의 `shot()` 은 이제 1.1초 기다린 뒤 찍는다(리뷰용 스크린샷이 실제 화면과 같도록).

## 2. 비판 메모(플레이어 + 설계자)

**첫 1분.** 로그인 → 명세 3줄 → 벨 → 카드 + 장면. 고치기 전에는 배너가 벨을 가리고, 첫 건에서 「검사」가 숨 쉬어 '짚어야 하나' 망설였다. 고친 뒤: 명세가 도장 색과 길게 누르기를 말하고, 첫 건은 들은 뒤 **초록 도장만 밝다** — 팝업 없이 확인을 한 번 하게 된다. 둘째 건(유자광 ↔ 이극돈)은 다름이 눈에 보이는데 파랑 도장이 쉬고 있어, 눌러 보면 안내 한 줄 + 「검사」가 크게 깜빡인다 → 짚기 → 빨간 실 → 파랑이 깨어난다. 60초 안에 확인/정정의 차이를 몸으로 안다.

**가독성.** 카드 본문 1.0625~1.3rem, 들은 말 1.0625rem, 명세·경고장 1rem 이상 — 충분. 낮은 대비는 관측 종료 부제(#67788a 계열)·바랜 07 손글씨 정도로 의도된 흐림. 실록 낱말 풀이(점선 밑줄)는 탭하면 바닥에 뜬다.

**촉감.** 도장(길게 누르기 + 진행 막대 + 자국 착지 + 07 각인)·실(빨강 고정 / 노랑 깜빡임 뒤 끊김)·프린터(경고장이 밀려 나옴)는 좋다. 흔들림을 더했다.

**긴장 곡선.** 근무 1 의 정점(서랍 → 회색 덮임 → 카드가 뒤집혀 바랜 07)은 잘 선다 — 단, 그 직후 화면 절반이 빈 상자였던 것이 여운을 깎았다(P1-1 로 해소). 근무 2 의 재생은 값(−60분)이 시계·근무 보고에 남아 좋고, 음악이 이제 긴장으로 바뀐다. 근무 3 은 노이즈(의심) → 재탐지(긴장 음악) → 보고서 → 복원(먹 번짐이 먼저, 경고장은 그 뒤 '해당 없음'으로).

**경고의 공정성.** 함정 3건 모두 경고 사유가 그 건의 역사 한 줄(묘호·이름 약칭·수 표기)이고 #C-2217 의 정답을 담지 않는다. 함정 건의 '정정'은 노랑을 짚어야만 깨어나므로, 경고를 받는 플레이어는 반드시 노란 깜빡임을 본 뒤다 — 경고가 "판단은 대조관"의 결과로 읽힌다(공정).

**함정의 가르침.** #A-0412 의 숨은 훙↔승하(노랑)는 그대로 둔다 — 「검사」가 첫 건에서 조용해졌으니 호기심으로 짚은 사람만 보는 보상이 됐다.

**복원·보상.** 일시 #### → 연산군 4년 7월 11일 먹 번짐, 권장 문구에 취소선, 경고장 '해당 없음', 메신저의 지난 문장 다시 쓰기(연필 표식 → 처음 문장). 에필로그 "기록은 돌아왔고, 그것을 기억하는 사람은 나 하나다" + 예고(07 의 관측 오류 2건)로 닫힌다.

**용어·역사 규칙 점검.** UI·데이터에 '졸'·'참조 수렴' 없음(grep). 복원 전 책상·관측·메신저에 4자리 연도 없음(e2e `noYearHere`). 보고서 '언제' 칸의 "붙인 자료가 가리키는 해"는 플레이어가 붙인 현대 DB 인물 기록(생몰)에서 나오는 값으로 v3 결정(DESIGN_V3 §1 6회, DESIGN_V4 §3.5)대로다. 검증 사실·출처·정답·provenance 는 건드리지 않았다(바꾼 데이터: 근무 명세 문구, 힌트 1줄 — 모두 fictional/재구성 안내문).

| R2-1 | 세로: 도장 뒤·관측 생략 건에서 카드와 도장 레일 사이가 휑하다 | 관측이 꺼진 세로 화면은 카드 칸이 `1fr` 로 남는 책상을 채운다(종이가 늘어나고 도장 자국은 아래, 레일은 맨 아래 고정). 관측 중에는 관측 창 최소 `33vh`(남는 칸은 `1fr` 로 더 가져감 → 390×844 에서 ≈39%), 카드 `26vh` 상한(안에서 스크롤). 트랙 크기가 뷰포트에서 정해지고 콘텐츠로 정해지지 않으므로 캔버스와 되먹임하지 않는다(JS 없음). |
| R2-2 | 긴 카드에서 장면이 작다 | `ObsWindow` 가 `ResizeObserver`(rAF 쓰로틀, 불리언이 바뀔 때만 setState)로 장면 높이를 재서 180px 미만이면 `.scene-small` — ⛶ 가 호박색으로 두 번 맥박친다(줄인 움직임이면 없음). |
| R2-3 | 근무 보고 중 위 띠가 `--:-- 0/-` | `TopStrip` 이 보고서가 열려 있으면(근무 해제 상태) 끝낸 근무의 마지막 시각·처리/목표·경고·시간 막대를 보여 준다(`selectShiftReport` + `dutyClock`, 스토어 변경 없음). 근무 밖(로그인)은 처리·경고를 흐리게. e2e 가 확인. |
| R2-4 | 가로 폰(≈915×412): 카드 칸이 150px 안팎, 근무 보고 「퇴근한다」가 스크롤 밑 | 번호판 변형이 레이아웃을 줄이지 않던 것을 음수 마진으로 바로잡고 도장·간격을 줄여 카드가 ≈35px 더 보인다. 근무 보고는 낮은 가로에서 2단(왼쪽 제목·오 실장, 오른쪽 수치·「퇴근한다」) — 스크롤 없이 한 화면. 업무 보고서 4칸은 2×2. |
| R2-5 | 데스크톱 구성 | ≥1200px 가로에서 책상 본체를 최대 1280px 로 가운데 정렬(위 띠 안쪽 여백도 맞춤). 1280×720 스크린샷에서 카드·관측 창이 의도한 비율. |
| R2-6 | 접근성 | `.desk-root :focus-visible` 호박색 3px 윤곽(도장·프린터·서랍은 안쪽 0 오프셋, 낱말은 파란 윤곽 + 배경), 도장·프린터·서랍 `aria-label` 은 이미 있어 e2e 로 고정, 새 애니메이션 모두 `prefers-reduced-motion` 에서 꺼짐(`os.css` 전역 규칙 + 개별 `animation: none`). |

남은 것: 세로 폰에서 카드가 긴 근무 2~3 건의 장면 높이는 여전히 ≈150px(⛶ 가 맥박으로 안내). 낮은 가로(≤420px)에서 카드 칸은 여전히 작아 안에서 스크롤한다.
